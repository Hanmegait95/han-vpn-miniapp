# Постоянный адрес для панели: panel.hanproject.ru

Сейчас панель живёт на временном туннеле Cloudflare
`hang-llp-affiliates-promotions.trycloudflare.com`. Имя выдаётся заново при
каждом запуске туннеля, а оно зашито внутрь каждой ссылки подписки — той
самой, по которой INCY ходит за обновлением серверов. Перезапустится
туннель — у всех разом перестанет обновляться VPN, и чинить придётся
выдачей новых ссылок каждому вручную.

**Сейчас в панели одна учётная запись, тестовая. Смена адреса стоит ноль.
После первых живых пользователей будет стоить дорого.**

## Что уже известно

| Что | Значение |
|---|---|
| Домен обслуживают | серверы Timeweb (`ns1…ns4.timeweb.ru/org`) |
| `panel.hanproject.ru` | свободно, записи нет |
| Перед панелью | веб-сервера нет, туннель воткнут прямо в приложение |
| Ссылка подписки | `https://<домен>/api/sub/<короткий id>` |
| `SUB_PUBLIC_DOMAIN` сейчас | голый домен, без пути |
| Токен доступа | к домену не привязан, менять не нужно |

## Шаг 1. Запись в DNS — панель управления Timeweb

Домены → `hanproject.ru` → DNS-записи → добавить:

    тип  A
    имя  panel
    значение  <внешний адрес сервера, где работает Remnawave>

Это единственное место, где нужен внешний адрес сервера. Если его нет
(панель дома, порты закрыты), этот путь не подходит — тогда нужен
постоянный туннель Cloudflare, а для него домен придётся перенести
на серверы Cloudflare.

Проверить, что запись разошлась:

    curl -s "https://dns.google/resolve?name=panel.hanproject.ru&type=A"

## Шаг 2. Веб-сервер с сертификатом — на сервере с панелью

Порты 80 и 443 должны быть открыты снаружи: без них сертификат
не выпустится. Caddy берёт его сам и продлевает сам.

    sudo apt install -y caddy

`/etc/caddy/Caddyfile` целиком:

    panel.hanproject.ru {
        reverse_proxy 127.0.0.1:3000
    }

Порт подставьте тот, в который сейчас смотрит туннель — его видно
в команде запуска `cloudflared` или в `docker compose ps`.

    sudo systemctl reload caddy

## Шаг 3. Два значения в настройках панели

В `.env` рядом с `docker-compose.yml`:

    FRONT_END_DOMAIN=panel.hanproject.ru
    SUB_PUBLIC_DOMAIN=panel.hanproject.ru

Без `https://`, без пути в конце: путь `/api/sub` панель добавляет сама,
и сейчас ссылки устроены именно так — если дописать его руками,
получится `/api/sub/api/sub`.

**Контейнеры нужно пересоздать, а не перезапустить** — перезапуск оставит
внутри старые значения:

    docker compose down && docker compose up -d

## Шаг 4. Проверка и выключение туннеля

    curl -sI https://panel.hanproject.ru | head -1     # ожидаем 200

Открывается — останавливайте `cloudflared`, он больше не нужен.

## Шаг 5. Скажите мне

Я поменяю адрес в настройках бота, прогоню самопроверку, перевыпущу
тестовую подписку и проверю всю цепочку целиком: выдача периода →
ссылка в мини-аппе → импорт в приложение → подтверждение от панели.
Это одна строка правки и несколько минут проверок.

## Чего это не решает

В панели нет ни одного узла и ни одного хоста, поэтому подписка отдаёт
заглушку с адресом `0.0.0.0`. Постоянный домен чинит адресацию, но не
даёт серверов: пока в панель не добавлен настоящий узел, VPN не заработает.
